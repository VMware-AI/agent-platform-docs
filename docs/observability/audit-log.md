# 审计日志

> 可观测性 → 审计日志 · <span class="ap-badge admin">admin</span> <span class="ap-badge readonly">read_only</span>

记录平台关键操作的审计轨迹，包含操作者、动作、资源与结果。合规检查、安全事件复盘、「谁把这个删了」都从这一页开始。

## 列

| 列 | 说明 |
|---|---|
| 操作时间 | 动作发生时刻 |
| 操作者 | 用户名或「系统」（平台自动任务） |
| 操作类型 | 见下方动作表，可下拉选择 |
| 资源类型 / 资源 ID | 被操作的对象，资源 ID 可一键复制 |
| 操作描述 | 人类可读的说明，支持搜索 |
| 结果 | 成功 / 失败 |
| IP 地址 | 操作来源 |
| 详情 | 展开完整记录 |

## 筛选

| 控件 | 选项 |
|---|---|
| 时间范围 | 过去 1 天 / 过去 7 天 / 自定义范围 |
| 类别 | 全部类别或指定资源类别 |
| 操作类型 | 全部或指定动作 |
| 结果 | 全部 / 成功 / 失败 |
| 列内搜索 | 操作者、资源类型、操作描述 |

## 常见审计场景

### 排查一次失败的部署

结果筛「失败」+ 类别筛「智能体」+ 时间锁定到部署那一刻 → 展开详情看失败原因（vCenter 权限、名称冲突、资源不足等）。

### 复盘一次误删

类别选被删对象类型 + 操作类型选「删除」→ 看操作者、时间与 IP。

### 合规季度报告

时间范围选整个季度 → 导出 CSV → 按需筛出所有涉及密钥签发 / 吊销、用户创建 / 删除、角色变更的记录。

### 排查异常登录

操作类型选「登录」→ 看 IP 地址分布与失败次数。

## 导出

点 **导出 CSV** 导出当前筛选结果。数据较多时会截断并提示已导出前 N 条。

::: tip 审计日志只增不改
平台不提供编辑或删除审计记录的入口 —— 这是审计有效性的前提。需要长期留存时，定期导出 CSV 归档到企业日志系统。
:::

## 与请求日志的区别

| | 审计日志 | [请求日志](/observability/request-log) |
|---|---|---|
| 记录什么 | **人在控制台上做的操作** | **agent 对模型发起的调用** |
| 典型问题 | 谁改了这个配置 | 那次调用为什么 429 |
| 保留价值 | 合规、安全 | 排障、对账 |
