# 实时监控

> 可观测性 → 实时监控 · <span class="ap-badge admin">admin</span> <span class="ap-badge readonly">read_only</span>

按时间窗口聚合网关请求指标，实时刷新关键指标卡片与时序图表。用于**当下**的健康判断；历史成本分析去[计量中心](/observability/metering)。

## 时间窗口与刷新

| 控件 | 选项 |
|---|---|
| 时间窗口 | 过去 1 小时 / 6 小时 / 24 小时 / 7 天 / 自定义范围 |
| 刷新间隔 | 5 秒 / 10 秒 / 30 秒 / 3 分钟 / 关闭 |
| 筛选 | 智能体 ID、模型 |

刷新按钮会显示当前间隔（如「刷新 (10 秒)」）。排查问题时建议调到 5–10 秒；长期挂在大屏上用 30 秒或 3 分钟即可。

## KPI 卡片

| 指标 | 说明 |
|---|---|
| 总请求数 | 窗口内的调用总量 |
| 平均延迟 | 平均响应时间 |
| P95 延迟 | 95 分位响应时间 —— 比平均值更能反映用户体感 |
| 输入 Token | prompt tokens |
| 输出 Token | completion tokens |

::: tip 看 P95 而不是平均
平均延迟被大量快请求拉低，P95 才能暴露「一部分人明显卡」的问题。P95 明显高于平均值时，去[请求日志](/observability/request-log)按延迟排序看最慢的那批。
:::

## 上游健康（各网关）

单独一块展示每个接入网关的健康状况：

| 状态 | 含义 |
|---|---|
| 健康 | 全部上游可达 |
| 部分异常 | 有模型降级或熔断，附「健康 N · 异常 M」计数 |
| 不可达 | 网关本身连不上 |

网关不可达时会明确提示「网关不可达」—— 这时候下面的图表数据也不会更新。

## 时序图表

| 图表 | 内容 |
|---|---|
| 请求量 | 窗口内请求数走势 |
| 延迟（平均 / P95） | 双线对比 |
| Token（输入 / 输出） | 双线对比 |
| 请求吞吐量 | Requests/sec |
| 平均响应时间 | ms |
| 活跃智能体数 | 同期在调用的实例数 |
| CPU 使用率 / 内存使用率 | 资源侧指标 |

每张图支持 **放大图表**，放大后按 Esc 或「退出放大」返回。

窗口内没有数据时显示「该时间窗口内暂无数据」。

## 典型排查路径

<ol class="ap-steps">
<li><strong>延迟突增</strong> —— 看 P95 曲线的拐点时间 → 到请求日志按该时间窗筛选 → 看是哪个模型 / 哪个智能体贡献的。</li>
<li><strong>请求量掉底</strong> —— 先看「上游健康」，网关不可达会直接导致所有调用失败；再看是否有密钥被禁用或超预算。</li>
<li><strong>Token 异常上涨</strong> —— 切到计量中心按智能体维度排行，定位到具体实例后检查是否有失控的循环调用。</li>
<li><strong>活跃智能体数下降</strong> —— 去<a href="/console/agents">智能体实例</a>看是否有实例转成了「异常」或「已停止」。</li>
</ol>

## 与 Grafana 的关系

平台还内置了一套 Grafana（默认 `http://<EXTERNAL_IP>:3000`，账号 `admin/admin`），预置了 LiteLLM 仪表盘与 Prometheus 数据源。

| 用途 | 去哪里 |
|---|---|
| 日常巡检、按智能体 / 模型看业务指标 | 本页（实时监控） |
| 深入的网关内部指标、自定义 PromQL | Grafana |

::: warning 记得改 Grafana 默认口令
Grafana 默认 `admin/admin`。生产环境请在 `.env` 里设置 `GRAFANA_ADMIN_USER` / `GRAFANA_ADMIN_PASSWORD` 后重新 `install.sh up`。
:::
