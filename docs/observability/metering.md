# 计量中心

> 可观测性 → 计量中心 · <span class="ap-badge admin">admin</span> <span class="ap-badge readonly">read_only</span>

按时间范围汇总网关调用量、Token 消耗与成本估算，支持按智能体与模型下钻。这是回答「这个月花了多少、花在谁身上」的地方。

## 两个数据源

页面顶部可切换**数据源**，两条链路完全独立：

| 数据源 | 来自 | 特点 |
|---|---|---|
| **平台记录** | 控制面自己的请求日志与计量表 | 带智能体归属，可与实例、密钥关联下钻 |
| **网关记录（litellm）** | 后端向各网关 fan-out 聚合 | 与网关账单口径一致，**计费源头** |

::: tip 两个口径对不上时以网关记录为准
网关记录直接来自 litellm 的账单表，是钱的源头。平台记录可能因为采集延迟、实例已回收、或请求日志摄入异常而略有差异。

差异持续偏大（超过几个百分点）说明请求日志采集有问题 —— 去看 `otel-collector` 容器状态。
:::

**网关记录**由后端聚合，各网关用各自的 master key，**前端不直连任何网关**。页面会显示每个网关的聚合状态（成功 / 失败 + 错误信息）—— 某个网关拉取失败时，总数是不完整的，界面上能看出来。

## 时间范围与筛选

| 控件 | 选项 |
|---|---|
| 时间范围 | 过去 7 天 / 过去 30 天 / 本月 / **自定义范围**（起、止） |
| 筛选 | 智能体 ID、模型；也可选「全部智能体」「全部模型」 |
| 操作 | 搜索 · 刷新 · 重置 |

## 汇总指标

顶部数字：

| 指标 | 说明 |
|---|---|
| 总花费 | 折算到展示币种后的金额 |
| 总 Token | 输入 + 输出 |
| 输入 Token | prompt tokens |
| 输出 Token | completion tokens |
| 活跃智能体 | 该窗口内有调用的实例数 |
| 活跃模型 | 该窗口内被调用过的模型数 |

## 维度视图

「维度」可切换四种分组：

| 维度 | 回答什么问题 |
|---|---|
| **按部门** | 哪个部门花得多 —— 月度分摊的依据 |
| **按模型** | 哪个模型最贵 —— 是否该把部分流量切到便宜模型 |
| **按密钥** | 哪把密钥消耗最多 —— 配合密钥的消费进度看 |
| **按智能体** | 哪个人 / 哪台机器用得最多；无法归属的记入**「未归属」** |

每个维度提供：

- **花费趋势** 折线（按日）
- **花费排行 Top 5**
- **明细表** —— 名称 / 花费 / 总 Token / 输入 / 输出

::: warning 「未归属」占比高说明绑定没做好
未归属 = 这些调用用的密钥没绑定智能体，或对应实例已被彻底删除。占比高就意味着成本分摊做不下去。解法是[部署时一机一密钥并完成绑定](/console/deploy#四实例配置清单)。
:::

## 统计表与下钻

三张统计表可切换：

| 表 | 列 |
|---|---|
| **按智能体** | 智能体 ID · 名称 · OVA 模板 · 总 Token · 请求次数 · 估算 Token · 状态 |
| **按模型** | 模型 · 输入 / 输出 / 总 Token · 请求次数 · 花费 |
| **按日期** | 日期 · 输入 / 输出 / 总 Token · 请求次数 · 花费 |

下钻路径：

- 点表格里的**智能体**或**模型** → 进入该对象的独立下钻页（独立趋势 + 明细）
- 点「智能体 × 模型」的组合 → 进入**组合详情页**，看某台机器在某个模型上的消耗

::: tip 排查「这个月怎么突然贵了」
① 按日期表找出金额跳变的那天 → ② 切「按智能体」找出那天涨得最多的实例 → ③ 下钻到该实例看它用了哪个模型 → ④ 到[请求日志](/observability/request-log)按该智能体 ID + 那一天筛，看是不是有失控的循环调用。
:::

## 成本估算摘要

底部给出**总计金额**与**月份预计成本**。预测口径在[计量设置](/observability/metering-settings)里切换：

- 按当月日均线性预测
- 按最近 7 天日均预测
- 不显示预测

## 预算视图

平台还维护按**部门 / 用户 / 密钥**三个作用域的预算数据，每条包含：已花费、预算上限（未设时为空）、剩余额度、**使用率百分比**、预算重置时间。

配合[计量设置](/observability/metering-settings)里的「月度预算告警」开关，超阈值时会汇总到总览仪表盘的「异常与待处理事项」。

## 导出

点 **导出 CSV** 导出当前筛选范围的数据。无数据时提示「当前无数据可导出」。

::: tip 月度对账流程
① 时间范围选「本月」→ ② 数据源切「网关记录」→ ③ 维度选「按部门」→ ④ 导出 CSV → ⑤ 与财务的分摊表比对。

有争议时再切到「按密钥」导一份，密钥能精确追到人。
:::

## 常见问题

| 现象 | 处理 |
|---|---|
| 无数据 | 放宽时间范围；确认筛选没过窄；点「重置筛选」 |
| 有 Token 但花费为 0 | 模型未配置单价 → [模型管理](/console/models) |
| 大量记录归到「未归属」 | 密钥没绑智能体，或实例已彻底删除 |
| 平台记录与网关记录差异大 | 请求日志采集异常，检查 `otel-collector` 容器 |
| 某个网关的数据缺失 | 该网关聚合失败，页面会标出错误信息；检查网关可达性与 Master Key |
| 金额币种不对 | [计量设置](/observability/metering-settings)里的「默认展示币种」与汇率 |
| 预计月底费用看着离谱 | 换个预测口径 —— 月初用「当月日均」会被前几天的波动放大 |
