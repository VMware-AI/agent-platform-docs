# 计量设置

> 计量中心 → 计量设置 · 需要 <span class="ap-badge admin">admin</span>

配置汇率及成本计算规则。分两个页签：**货币与汇率** 和 **成本规则**。

这一页决定了[计量中心](/observability/metering)和总览仪表盘上那些数字**是怎么算出来的**。装完平台之后花十分钟把它配好，后面对账能省很多事。

## 货币与汇率

### 币种设置

| 字段 | 说明 |
|---|---|
| **基准币种** | 把不同模型和供应商的成本**归一**为统一货币 |
| **默认展示币种** | 只影响前端展示，**不修改原始费用** |
| 金额显示精度 | 前端展示的小数位数；后端始终保留高精度 |
| 保留原始费用 | 保留原始金额、币种及汇率快照，**始终开启不可关** |

::: tip 原始金额永远不会被改写
展示币种与精度只是「看」的方式。每条费用记录都保存了原始金额、原始币种与**当时的汇率快照**，历史账单可追溯、可复算 —— 今天改汇率不会让上个月的账单变一个数。
:::

::: warning 精度别设太小
Token 单价常常是 `0.0000015` 这个量级，显示精度设成 2 位的话，小额条目会全部显示成 0.00，看着像没花钱。建议 4 位起步。
:::

### 汇率管理

维护币种对的换算关系：

| 字段 | 说明 |
|---|---|
| 币种对 | 原始币种 → 目标币种 |
| 换算关系 | 方向说明 |
| 汇率值 | 换算系数 |
| 来源 | 手动维护 / 系统默认 |
| 状态 | 启用 / 停用 |
| 生效时间 / 失效时间 | 汇率的有效区间 |
| 备注 | 说明来源与依据 |
| 更新人 / 更新时间 | 审计信息 |

操作：**添加汇率** · **编辑** · **停用** · **历史**。

::: warning 停用不影响已产生的账单
确认停用时会提示「已产生账单不受影响」—— 历史记录用的是当时的快照。
:::

**汇率历史**保留每一次变更的版本，可随时回看某个时点用的是哪个值。没有记录时显示「暂无历史版本」。

::: tip 备注字段值得认真填
「按 2026-08-01 中行中间价」这样一句话，半年后财务来问的时候能省掉一小时考古。
:::

### 换算验证

底部的小工具：填**金额** + **原始币种** + **目标币种**，选一个汇率，即时看到换算结果。

明确标注：**换算验证只用于确认配置，不创建任何账单。**

## 成本规则

### 价格缺失处理

当模型未配置价格时如何处理费用计算：

| 选项 | 行为 | 适用 |
|---|---|---|
| **标记为价格待配置，调用继续** | 不阻断业务，费用留空待补 | ✅ 推荐默认 |
| 按 0 临时计算并产生告警 | 费用记 0，同时告警提醒 | 想让账面连续、但接受短期失真 |
| 拒绝生成费用记录 | 不生成该条费用记录 | 财务口径极严、宁缺勿错 |

::: tip 为什么推荐「标记为待配置」
业务不受影响，同时能在计量中心一眼看出哪些模型缺价格。选「按 0 计算」的话，缺价格的调用会悄悄变成免费，等到月底对账才发现差了一大截。

补上单价后重新统计即可。
:::

### 缓存 Token 计算

两个独立开关：**计算缓存读取 Token**、**计算缓存写入 Token**。

是否把缓存命中产生的 token 计入费用，取决于上游供应商的计费口径 —— 和[模型管理](/console/models)里配的「缓存读取单价 / 缓存写入单价」配套使用。

::: warning 口径要和供应商对齐
供应商按缓存读取半价计费、而你这里关掉了缓存 token 计算，账面就会系统性偏低。开票金额对不上时先查这两个开关。
:::

### 金额舍入规则

四舍五入 / 向上取整 / 向下取整。

### 月末费用预测

| 选项 | 算法 | 什么时候准 |
|---|---|---|
| 按当月日均线性预测 | 当月累计 ÷ 已过天数 × 当月总天数 | 用量平稳时 |
| 按最近 7 天日均预测 | 近 7 天日均 × 当月总天数 | 用量在爬坡或刚扩容 |
| 不显示预测 | 隐藏仪表盘与计量中心的预测值 | 不想被不准的数字误导 |

::: tip 月初别信线性预测
月初只过了两三天，「当月日均」被这几天的波动放大得厉害，预测值经常离谱。月初用「最近 7 天」更稳，月中之后两者趋同。
:::

### 告警设置

四类开关：

| 告警 | 触发条件 |
|---|---|
| **价格缺失告警** | 有模型没配单价 |
| **汇率缺失告警** | 需要换算但没有对应汇率 |
| **月度预算告警** | 接近或超出预算 |
| **用量异常增长告警** | 用量陡增 |

告警会汇总到[总览仪表盘](/console/overview)的「异常与待处理事项」。

::: tip 至少开前两个
价格缺失和汇率缺失是**数据质量**问题，不开告警就只能等到对账时才发现。这两个几乎没有噪音，开着不烦人。
:::

## 三套配置模板

| 场景 | 建议 |
|---|---|
| **单一币种、内网自建模型** | 基准与展示币种一致；不用配汇率；价格缺失选「标记为待配置」；开价格缺失告警 |
| **多供应商、多币种** | 认真维护汇率与生效区间，备注写清来源；开汇率缺失告警；精度 4–6 位 |
| **需要向财务出账** | 精度 ≥ 4；缓存 token 口径与供应商对齐；开月度预算告警；月末用「按当月日均」预测；每月导出 CSV 归档 |

## 常见问题

| 现象 | 处理 |
|---|---|
| 计量里全是 0.00 | 显示精度太小，调到 4 位以上 |
| 有 Token 但没费用 | 模型未配单价 → [模型管理](/console/models) |
| 换算结果不对 | 检查汇率方向（币种对的换算关系）与生效区间 |
| 和供应商账单差一截 | 先对缓存 token 口径，再对舍入规则 |
| 预测值忽高忽低 | 换成「最近 7 天日均」，或先关掉预测 |
| 改了汇率，历史账单变了吗 | 不会。历史用的是当时的汇率快照 |
