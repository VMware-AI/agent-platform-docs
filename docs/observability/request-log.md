# 请求日志

> 可观测性 → 请求日志 · <span class="ap-badge admin">admin</span> <span class="ap-badge readonly">read_only</span>

查看经由网关代理的上游模型请求记录。**逐条**级别的事实来源 —— 监控告诉你「有问题」，请求日志告诉你「是哪几条请求出的问题」。

## 列

| 列 | 说明 |
|---|---|
| 时间 | 请求发生时刻 |
| 智能体 / 智能体 ID | 发起方，支持按 UUID 或名称搜索 |
| 模型 | 调用的路由 / 模型名，支持搜索 |
| 用户 | 关联用户，支持按 ID 或名称搜索 |
| 状态 | HTTP 状态码，可按状态码分组筛选 |
| 响应时间 | 延迟（ms） |
| Token (入/出) | 输入 / 输出 token，悬停显示明细 |
| 请求 ID | 唯一标识，可一键复制 |
| 详情 | 展开单条记录的完整信息 |

## 筛选

| 控件 | 选项 |
|---|---|
| 时间范围 | 过去 1 小时 / 6 小时 / 自定义范围（起、止） |
| 状态码 | 全部 / 按状态码分组 |
| 列内搜索 | 智能体、模型、请求 ID、用户 |

已应用筛选时会有提示，可 **清除** 单项或 **清除全部筛选**。

## 导出

点 **导出 CSV**。数据量大时会截断并提示「数据较多，已导出前 N 条」—— 需要完整数据请先缩小时间范围再分批导出。

## 排障用法

### 用户报「agent 报错了」

1. 时间范围选事发前后 1 小时
2. 状态码筛 4xx / 5xx
3. 智能体列搜该用户的实例名
4. 展开详情看具体错误

常见状态码对照：

| 状态码 | 通常原因 |
|---|---|
| 401 | 虚拟密钥无效 / 被禁用 / 过期 / 超预算 |
| 403 | 密钥作用域不含该模型 |
| 404 | 请求的模型名不存在（写成上游原名而不是路由名） |
| 429 | 触发 RPM / TPM / 并发限制 |
| 5xx | 上游模型服务异常 —— 去[模型管理](/console/models)看健康状态 |

### 找最慢的请求

按响应时间排序，取 Top N 看它们的共同点：同一个模型？同一个时间段？同一台智能体？

### 对账

某个智能体的账单对不上时，用智能体 ID 筛出全部记录，导出 CSV 与[计量中心](/observability/metering)的汇总比对。

## 数据是怎么进来的

```
litellm 网关 ──OTLP──▶ otel-collector ──写入 jsonl──▶ backend 摄入 worker ──▶ PostgreSQL
```

`otel-collector` 容器是 v0.0.1 引入的采集环节，跑在回环 4317/4318。

::: warning 请求日志一直为空
按顺序检查：① 智能体是否真的通过网关调用了模型（看实时监控的请求量）② `otel-collector` 容器是否 running ③ backend 日志里 requestlog 摄入相关的报错。
:::
