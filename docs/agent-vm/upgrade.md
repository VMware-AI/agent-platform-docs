# 升级与回滚

智能体的版本升级**在 VM 内完成**，不需要重建虚拟机、不丢工作数据。有两条触发路径：管理员从控制台批量下发，或使用者在 VM 管理台自助操作。

## 路径一：管理员从控制台下发

> 智能体实例 → 版本更新 · 需要 <span class="ap-badge admin">admin</span>

单台或批量选中实例后点「版本更新」：

| 字段 | 说明 |
|---|---|
| 目标版本 | 从内网镜像安装该版本包。版本号只允许字母数字与 `.` `_` `-`（不含路径 / 空格） |

- **单台**：「将为『xxx』下发升级命令，VM 内 agent-manager 会在下次心跳时拉取安装。」
- **批量**：「将为选中的 N 个智能体下发同一升级命令（各自下次心跳时执行）。」

::: tip 升级是异步的
控制台只负责**下发命令**，实际安装发生在各 VM 的下一次心跳。批量下发后各台独立推进，互不影响。稍后回列表看版本列确认结果。
:::

## 路径二：使用者在 VM 管理台自助

打开 `https://<VM_IP>/manage/`：

1. 页面列出**当前版本**、**本地已装版本**、**服务端可拉取版本**
2. 选一个版本点升级
3. 需要退回时点回滚，留空则退回**上一版本**（一键 undo）

## 升级时 VM 内做了什么

```
① 拉取 {name}-{version}.tar.gz
   （FTP 或 http/s —— 平台配置的 AGENT_PKG_BASE_URL 给什么用什么）
② sha256 校验
③ 安全解压到 versions/<版本号>        ← 防路径穿越
④ 切换 current 符号链接
⑤ restart systemd 单元
⑥ 失败 → 自动回滚到上一版本
⑦ 清理旧版本（保留最新 N 个）
```

::: tip 为什么升级很安全
每个版本装在独立目录，`current` 只是一个符号链接。升级失败会自动切回去，回滚也只是把链接指回旧目录 —— 不重新下载、秒级完成。
:::

## 回滚

回滚**不拉包**，只在已安装的版本之间切换 + 重启服务：

- 指定目标版本 → 切到该版本
- 留空 → 切回上一版本

因此只有还留在本地的版本才能回滚。旧版本会按「保留最新 N 个」的策略清理，太老的版本清掉后就回不去了，只能重新升级安装。

## 版本包从哪来

包源地址由平台配置：优先读数据库里的**平台设置**，其次回退到环境变量 `AGENT_PKG_BASE_URL`。支持 FTP 与 HTTP/S 两种协议，用于**完全离网**的内网分发。

保留版本数由 `AGENT_KEEP_VERSIONS` 控制。

## 与「重新部署」的区别

| | 版本更新（本页） | 重新部署 |
|---|---|---|
| VM | 复用原 VM | 新建 VM |
| 工作数据 | **保留** | 丢失（除非手工迁移） |
| IP / 凭据 | 不变 | 重新分配 |
| 耗时 | 一次心跳 + 安装 | 5–10 分钟 |
| 适用 | agent 版本迭代 | 换模板族、换 OS、实例损坏 |

日常 agent 版本迭代**用版本更新**；只有换模板或实例彻底损坏时才重新部署。

## 常见问题

| 现象 | 处理 |
|---|---|
| 下发后版本没变 | 等待下一次心跳；确认 VM 能访问包源地址；看 VM 内 `journalctl -u agent-manager` |
| 提示版本号非法 | 只允许字母数字与 `.` `_` `-`，不能含路径分隔符或空格 |
| 升级后 agent 起不来 | 系统会自动回滚；仍异常则手工回滚到上一版本并联系管理员 |
| 想回滚但版本不在列表里 | 该版本已被清理，只能重新升级安装 |
| 包下载失败 | 包源地址不可达或该版本包不存在，联系管理员确认内网仓库 |
