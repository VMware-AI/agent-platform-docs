# 核心概念

控制台里的对象之间有明确的依赖顺序。先对齐这些术语，后面的配置步骤就只是照着填。

## 对象关系一览

```
资源池（vCenter）
   └─ 内容库 → OVA 模板族 → 模板版本
                                └─ 部署 ──▶ 智能体实例（VM）
                                                 │
模型网关（LiteLLM）                               │ 绑定
   ├─ 供应商模型（上游真实模型 + API Key）          │
   ├─ 网关路由（路由策略 + 降级链）                 │
   └─ 虚拟密钥（作用域 / 限流 / 预算）  ◀───────────┘
```

## 底座类

### 资源池（Resource Pool）

一个**已接入的 vCenter**，是智能体运行的物理底座。接入时填 VC 地址、账号口令，并选择存放 OVA 模板的**内容库（Content Library）**。接入成功后平台会同步该 vCenter 的资产：集群、数据存储、网络（端口组）、VM 文件夹、存储策略、主机、资源池。

→ [资源池接入](/console/resource-pools)

### 模型网关（Model Gateway）

一个**已接入的 LiteLLM Proxy 实例**，是所有模型调用的数据面入口。接入时填网关地址、Master Key，以及 **Agent 访问地址**（智能体 VM 侧用来访问网关的 URL，可能与控制面看到的地址不同）。平台会自动与网关同步模型目录、路由策略与连接状态。

→ [模型网关接入](/console/gateway-connections)

## 模型类

### 供应商模型（Supplier Model）

登记在平台里的**上游真实模型**：供应商分类（如 `openai` / `azure` / `vllm`）、上游模型原名、API Base、API Key、限流参数与单价。API Key 由后端加密入库，前端不再回显。

一条「模型」记录下可以挂多个**供应商模型规格（spec）**，用于同名模型的多实例负载。每个 spec 有独立的健康状态：健康 / 降级 / 熔断 / 未探测。

→ [模型管理](/console/models)

### 网关路由（Gateway Route）

对外暴露的**逻辑模型名**，把请求按策略分派到一组供应商模型上。可选策略：

| 策略 | 含义 |
|---|---|
| 简单洗牌（SIMPLE_SHUFFLE） | 随机分流 |
| 最闲优先（LEAST_BUSY） | 选当前并发最少的 |
| 延迟优先（LATENCY_BASED_ROUTING） | 选历史延迟最低的 |
| 使用率优先（USAGE_BASED_ROUTING_V2） | 按用量均衡 |
| 成本优先（COST_BASED_ROUTING） | 选单价最低的 |

还可以配置三类**降级链**：常规故障转移、上下文超限降级、内容策略降级。

→ [网关路由](/console/routes)

### 虚拟密钥（Virtual Key）

发给调用方的 **API 密钥**（`sk-…`）。密钥不是裸的通行证，而是一组治理参数的载体：

- **作用域** —— 可调用哪些模型、哪些接口
- **限流** —— RPM / TPM 上限、最大并发
- **预算** —— 消费上限与消费进度
- **生命周期** —— 有效时长、自动轮换周期、启用 / 禁用 / 吊销
- **归属** —— 绑定到某个智能体实例，用于成本归属

部署智能体时会把密钥注入到 VM 里，agent 用它调用网关。

→ [密钥管理](/console/keys)

## 智能体类

### OVA 模板族与版本（Template Family / Version）

**模板族**是一类智能体（如 OpenClaw、Hermes、OpenCode、QCoder、小怪），带描述、预装工具、预装技能与适用场景；**版本**是该族下具体的 OVA 模板，指向内容库里的一个 OVF/OVA 标识符。部署时选族 + 选版本。

→ [智能体市场](/console/marketplace)

### 智能体实例（Agent Instance）

一台**已部署的智能体虚拟机**，是平台的核心运行单位。实例有名称、类型、状态、绑定密钥、运行账户、访问端点。

| 状态 | 含义 |
|---|---|
| 部署中（PROVISIONING） | 克隆 / 开机 / 等待注册中 |
| 运行中（RUNNING） | 心跳正常 |
| 已停止（STOPPED） | VM 已关机 |
| 异常（EXCEPTION） | 心跳超时或部署失败 |
| 已回收（RECYCLED） | 已删除释放，记录保留用于审计与账单 |

→ [智能体实例](/console/agents)

### 技能（Skill）

给智能体扩展能力的**可安装包**（pip / npm / 二进制，可带 MCP 配置）。平台维护一个离线技能库：在线下载或本地上传到跳板机后，可批量安装到指定 agent VM。

→ [技能管理](/console/skills)

### 知识包（Knowledge Pack）

挂在**智能体配置**上的离线知识资料包。部署时随 guestinfo 授权列表下发，VM 内 agent-manager 在心跳时拉取、校验 sha256、安全解压到知识根目录。属于本地文件分发，不是 RAG 索引。

## 治理类

### 角色

平台内置三个角色：

| 角色 | 定位 |
|---|---|
| <span class="ap-badge admin">admin</span> 超级管理员 | 平台全量读写：接入、部署、发密钥、管用户 |
| <span class="ap-badge readonly">read_only</span> 只读用户 | 观测岗：可看计量、监控、请求日志、审计日志，从不写 |
| `user` 普通用户 | 只看自己名下的资源 |

→ [角色与权限矩阵](/reference/roles)

### 计量与审计

- **计量**：按时间窗聚合调用量、Token 与成本，可按部门 / 模型 / 密钥 / 智能体下钻。数据源可选「平台记录」或「网关记录（litellm）」。
- **请求日志**：每一次经网关代理的上游调用（模型、Token、延迟、状态码、请求 ID）。
- **审计日志**：平台侧关键操作轨迹（操作者、动作、资源、结果、IP）。

→ [可观测性](/observability/metering)
