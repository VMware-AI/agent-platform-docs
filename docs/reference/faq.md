# 常见问题

## 关于版本

**Q：v0.0.1 包含哪些部署形态？**
发布 **4 个形态**，每个是独立 tarball：`dc-standalone`（单机开发）、`dc-distribution`（本地多服务）、`k8s-standalone`（k8s 小集群）、`k8s-ha`（k8s 生产 HA）。k8s-* 形态自带完整 Helm chart（templates + values 文件）。

**Q：v0.0.1 还有离线镜像包吗？**
**没有了。** release 只发布 4 个安装 tarball，`install.sh` 默认从 `quay.io/vmware-ai/<image>` 拉镜像。需要完全离网时按 [离线安装（单机）](/install/dc-standalone#6-离线安装可选气隙环境) 在能上网的机器上 `make package-images-amd64`（或 `arm64`）自己造一份镜像包。

**Q：支持 arm64 吗？**
支持 —— `install.sh` 自动按主机架构选镜像。如果走气隙安装，用 `make package-images-arm64` 出对应架构的镜像包就行。

**Q：能装在 k8s 上吗？**
v0.0.1 已经可以。用 `agent-platform-k8s-standalone-<v>.tar.gz`（自带 PG/Redis）或 `agent-platform-k8s-ha-<v>.tar.gz`（需外部 PG/Redis），分别覆盖小集群与生产 HA 两个场景。

**Q：单机形态能撑多少智能体？**
控制面是单副本，主要瓶颈在数据库与请求日志摄入。评估阶段的经验值是几十台没问题；规模上量之后建议等 HA 形态。

## 关于安装

**Q：必须联网吗？**
默认安装**需要**目标机能访问 `quay.io`（拉镜像）。完全离网 / 气隙环境用 [离线安装（单机）](/install/dc-standalone#6-离线安装可选气隙环境) —— 先在能上网的机器上造镜像包、再带到目标机作为同级目录放好。装好之后，唯一必需的外部连接是**平台主机到 vCenter 的 443**，以及到内网模型服务。

**Q：`install.sh` 说 `EXTERNAL_IP` 非法？**
必须填浏览器真正会输入的地址。不接受空值、`0.0.0.0`、`localhost`、`127.x.x.x`、`::1`。

**Q：为什么访问 `https://<IP>:80/` 打不开？**
安装横幅在 v0.0.1 会显示 `:80`，这是文案问题。实际 HTTPS 在 **443**，直接访问 `https://<EXTERNAL_IP>/` 即可。

**Q：能改控制台端口吗？**
`.env` 里的 `CONSOLE_PORT` 在本形态下不改变实际映射。需要换端口只能改 `manifests/docker-compose.yml` 里 console 的 `ports:`，然后 `./install.sh up`。

**Q：可以用自己的证书吗？**
可以。把 `SSL_CERT_PATH` / `SSL_KEY_PATH` 指向你的文件，重跑 `./install.sh up`。见[网络与证书](/install/network-tls)。

**Q：`install.sh` 能重复执行吗？**
能，而且这是「应用配置改动」的推荐方式。已生成的密钥不会被覆盖，已有证书不会被替换。

**Q：装到一半失败了怎么办？**
`./install.sh down` 停掉，修完问题重跑 `./install.sh`。数据卷会保留。

## 关于登录

**Q：初始账号密码是什么？**
`admin@platform.local` / `.env` 里的 `ADMIN_BOOTSTRAP_PASSWORD`（默认 `ChangeMe123!`，**请立即改掉**）。

**Q：浏览器提示证书不受信？**
正常，默认是自签名证书。点「高级 → 继续访问」。

**Q：登录后所有请求都失败 / 控制台白屏？**
多半是 CORS。`.env` 的 `ALLOWED_ORIGINS` 要包含你正在使用的 URL，改完 `docker compose -p agent-platform restart backend`。

**Q：忘记管理员密码？**
改 `.env` 里的 `ADMIN_BOOTSTRAP_PASSWORD` 后 `docker compose -p agent-platform restart backend`。

**Q：为什么强制我改密码？**
账号被标记为「需要修改密码」（首次使用 bootstrap 口令、或管理员刚重置过）。改完就正常了。

## 关于智能体

**Q：一台 VM 能跑几个 agent？**
设计上是 **1 用户 = 1 隔离 VM = 1 agent**。隔离性与成本归属都建立在这个前提上。

**Q：智能体一直停在「部署中」？**
两个高频原因：① 静态 IP 配错，VM 拿不到网络；② VM 无法出站访问控制面 443。

**Q：升级 agent 会丢数据吗？**
不会。升级在 VM 内完成，装到独立的版本目录再切符号链接，工作数据不受影响。见[升级与回滚](/agent-vm/upgrade)。

**Q：删除的实例还在列表里？**
删除后转「已回收」，保留记录用于审计与历史账单。要彻底清除用「彻底删除」。

**Q：能给已有的实例换模板吗？**
不能。换模板族需要重新部署。日常版本迭代用「版本更新」。

**Q：运行中的实例能缩 CPU / 内存吗？**
不能，运行中只支持扩容。先停止实例再改。**磁盘任何状态下都只能扩。**

**Q：控制台为什么没有快照按钮？**
v0.0.1 界面未暴露。后端支持快照与回滚（审计日志里能看到相应动作），需要时直接在 vCenter 侧对 VM 操作 —— 智能体 VM 是完全独立的清单对象。

**Q：批量部署最多多少台？**
没有硬性上限，受 vCenter 并发与数据存储吞吐制约。建议一次 10–20 台，用即时克隆能显著加快。

## 关于模型与密钥

**Q：智能体调用报 401 / 403 / 404 / 429？**

| 状态码 | 原因 |
|---|---|
| 401 | 密钥被禁用 / 过期 / 吊销 / 超预算 |
| 403 | 请求的接口类型不在密钥的「可调用接口」作用域内 |
| 404 | 请求里写的不是**路由名** |
| 429 | 触发 RPM / TPM / 并发限制 |

**Q：控制台测试网关正常，但 agent 调不通？**
两者用的是不同地址。控制台测的是「网关地址」，agent 用的是「**Agent 访问地址**」。排查后者的连通性 —— 这是最高频的坑。

**Q：模型显示「熔断」怎么恢复？**
修好上游后到[模型管理](/console/models)点「解除熔断」。**熔断不会自动恢复**。

**Q：密钥明文丢了？**
无法找回。删掉旧密钥重新颁发一把，或用「重新生成」换新密钥，然后更新到 VM 里。

**Q：路由名有什么限制？**
大写字母、数字与中划线，2–64 字符。建议用稳定的**能力名**（`CODE-FAST`）而不是型号名，底层换模型时不用改 agent 配置。

**Q：一把密钥能给多台机器用吗？**
技术上可以，但不建议 —— 成本无法归属到人，出问题也没法精确止血。

## 关于计量与账单

**Q：有 Token 但费用是 0？**
模型没配单价。到[模型管理](/console/models)补上输入 / 输出单价。

**Q：计量中心和网关账单对不上？**
以「网关记录（litellm）」数据源为准，它是计费源头。平台记录可能因采集延迟略有差异；差异持续偏大说明请求日志采集有问题。

**Q：为什么很多记录归到「未归属」？**
这些调用的密钥没绑定智能体，或对应实例已被彻底删除。建议一机一密钥并在部署时完成绑定。

**Q：请求日志一直是空的？**
检查 `otel-collector` 容器是否 running，以及 backend 日志里的摄入报错。

**Q：预计月底费用看着离谱？**
月初用「当月日均线性预测」会被前几天波动放大。换成「最近 7 天日均」，见[计量设置](/observability/metering-settings)。

**Q：改了汇率，历史账单会变吗？**
不会。每条费用记录都保存了当时的汇率快照。

## 关于安全

**Q：数据会离开企业内网吗？**
不会 —— 只要上游模型也部署在内网。所有调用经内网网关代理，控制面不主动外联。

**Q：平台保存智能体 VM 的登录密码吗？**
不保存明文。密码在部署时经 guestinfo / vApp 属性注入，VM 本地也只存指纹。

**Q：模型的 API Key 存在哪？**
加密存在 `platform_secrets` 表，用 `SECRETS_ENCRYPTION_KEY` 加密，前端永不回显。

**Q：谁能看审计日志？**
`admin` 与 `read_only`。审计记录只增不改，平台不提供编辑 / 删除入口。

**Q：备份需要保留什么？**
最关键的是 `.secrets_encryption_key` 和 `.env`，其次是两个数据库。见[备份清单](/install/upgrade#备份清单)。

**Q：能做更细粒度的角色吗？**
v0.0.1 只有三个内置角色。见[角色与权限矩阵](/reference/roles#更细的授权)。

**Q：VM 之间能互相访问吗？**
默认取决于你的网络策略。**强烈建议**用 NSX 微分段禁止横向流量，见[端口与网络](/reference/ports#nsx-微分段建议)。

## 关于文档

**Q：能把这份手册带进内网离线看吗？**
可以。有离线包，解压后 `sudo ./install.sh` 部署到自己的 nginx，全站含搜索都能离线用。见[离线部署本手册](/reference/offline-docs)。

**Q：文档和实际界面对不上？**
本手册对齐的是 v0.0.1。版本不同可能有差异 —— 以「关于」对话框里的版本号为准，并把差异反馈给我们。
