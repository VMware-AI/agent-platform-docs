# 角色与权限矩阵

平台内置三个角色。权限判定发生在后端 GraphQL 层，前端路由守卫只是提前拦截，**不是安全边界** —— 绕过前端也拿不到数据。

## 三个角色

| 角色 | 中文名 | 定位 |
|---|---|---|
| `admin` | 超级管理员 | 平台全量读写 |
| `read_only` | 只读用户 | 观测岗：可看计量与审计，**从不写** |
| `user` | 普通用户 | 只读自己名下的资源 |

## 权限点

| 权限点 | 覆盖什么 | admin | read_only | user |
|---|---|:---:|:---:|:---:|
| `agent:manage` | 智能体部署 / 启停 / 删除 | ✅ | — | — |
| `key:manage` | 虚拟密钥签发 / 吊销 | ✅ | — | — |
| `route:manage` | 模型与路由配置 | ✅ | — | — |
| `user:manage` | 用户与角色管理 | ✅ | — | — |
| `audit:view` | 审计日志 / 请求日志 | ✅ | ✅ | — |
| `metering:view` | 计量中心 / 实时监控 | ✅ | ✅ | — |

::: tip 写操作恒为 admin
权限矩阵刻意只给 `read_only` 两个 **view** 权限。所有写操作（mutation）按构造只对 `admin` 开放 —— 这样「观测岗永远不会误写」不依赖任何额外判断。
:::

访问无权页面时会被**重定向到总览**，而不是停在一个所有请求都报错的空页面上。

## 该给谁什么角色

| 人 | 角色 | 理由 |
|---|---|---|
| 平台运维、部署负责人 | `admin` | 需要接入底座、部署实例、发密钥 |
| 安全 / 合规 / 财务对账 | `read_only` | 需要看审计与账单，不应改配置 |
| 智能体使用者 | `user` | 只需要看自己那台机器；日常操作在 VM 管理台完成 |

::: warning admin 账号要收敛
admin 可以删除资源池、彻底删除实例、吊销全部密钥。建议只给必要的少数人，并靠[审计日志](/observability/audit-log)追踪其操作。
:::

## 角色变更

在[用户与权限](/console/users)页对某个用户点「更换角色」。变更立即生效，用户下次导航时按新角色重新判定。变更本身会记入审计日志（动作：分配角色 / 移除角色）。

## 与 VM 内权限的关系

平台角色只管**控制台**。智能体 VM 内部是另一套：使用者用 OS 账户登录自己那台机器，能力边界由 VM 的 OS 权限与 [VM 自服务管理台](/agent-vm/webadmin) 决定。两者不互通 —— 平台的 `admin` 不会自动获得任何 VM 的 root。
