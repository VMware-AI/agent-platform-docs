# 密钥管理

> 模型调度台 → 密钥管理 · 需要 <span class="ap-badge admin">admin</span>

颁发和管理调用方使用的 API 密钥（虚拟密钥），支持额度与作用域控制。密钥是平台治理的核心抓手 —— **每个智能体绑一把密钥，成本、限流、可用模型与止血开关都挂在它上面。**

## 一把密钥携带什么

密钥不是一串裸的通行证，而是一组治理参数的载体：

| 维度 | 字段 |
|---|---|
| 身份 | 名称、掩码、密钥类型、所属组织、所属模型网关 |
| 归属 | 绑定的智能体 —— 成本按此归集 |
| 作用域 | 可调用模型、可调用接口 |
| 限流 | RPM / TPM 上限及其模式、最大并发 |
| 预算 | 消费上限、预算周期、已消费金额、消费进度 |
| 生命周期 | 有效时长 / 过期时间、自动轮换及周期、启用 / 禁用 / 吊销 |
| 观测 | 最近活动时间、创建 / 更新时间、标签 |

## 颁发密钥

点 **颁发密钥**：

### 基本

| 字段 | 说明 |
|---|---|
| 密钥名称 | 平台内唯一；重名会实时提示「该名称已被使用」 |
| 模型网关 | 该密钥归属的网关。**选完网关才会加载可调用模型列表** |
| 绑定的智能体 | 可留空后续再绑；绑定后成本归属到该实例 |
| 标签 | 用于分组与检索，如部门名、项目号 |

### 作用域

| 字段 | 说明 |
|---|---|
| 可调用模型 | 从该网关的路由列表里勾选；**不选 = 全部** |
| 可调用接口 | `CHAT` / `EMBEDDINGS` / `IMAGES` / `AUDIO`；不选 = 全部 |

::: tip 接口作用域是个被低估的开关
只做代码补全的 agent 不需要 `IMAGES` 和 `AUDIO`。把作用域收窄到 `CHAT`，密钥泄漏后的滥用面就小一大截。
:::

### 有效期

| 字段 | 说明 |
|---|---|
| 有效时长 | 数值 + 单位（小时 h / 天 d / 周 w / 月 m），如 `30d`。**留空 = 永不过期** |
| 过期时间 | 也可以直接指定一个绝对时间点 |

### 治理参数

| 字段 | 说明 |
|---|---|
| 消费上限 | 累计花费封顶；达到后调用被拒 |
| 预算周期 | 上限的重置周期，如按月重置 |
| 最大并发 | 同时在飞的请求数上限 |
| RPM 限制 / TPM 限制 | 每分钟请求数 / Token 数上限 |
| RPM 模式 / TPM 模式 | `guaranteed_throughput`（保量）/ `best_effort`（尽力） |

::: tip 两种限流模式怎么选
- **保量（guaranteed_throughput）** —— 给这把密钥预留配额，适合关键业务 agent
- **尽力（best_effort）** —— 有余量就给，适合探索性、非关键的 agent

全给保量会把网关配额吃满，其余密钥被饿死；建议只给少数关键密钥设保量。
:::

### 自动轮换

| 字段 | 说明 |
|---|---|
| 自动轮换 | 开启后按周期自动换发新密钥 |
| 轮换周期 | 数值 + 单位（秒 s / 分钟 m / 小时 h / 天 d） |

::: warning 开自动轮换前先确认下游能拿到新密钥
轮换会让旧密钥失效。智能体侧需要有拿到新密钥的通路，否则轮换的那一刻业务就断了。不确定就先不开，用「定期手工 regenerate + 更新到 VM」的方式。
:::

::: danger 密钥明文只显示一次
颁发成功后弹出一次性对话框展示完整密钥（`sk-…`）。**关闭后无法再次查看**，列表里只保留掩码。请立即复制并妥善保存。
:::

## 列表

| 列 | 说明 |
|---|---|
| 名称 | 密钥名 |
| 绑定的智能体 | 成本归属对象 |
| 所属模型网关 | 归属网关 |
| 可调用模型 | 作用域内的路由；超出显示「再显示 N 个」 |
| 密钥 | 掩码 |
| 状态 | 启用 / 禁用（后端还有 `revoked` 吊销态） |
| 过期时间 | 到期后自动失效 |
| **消费进度** | 已用 / 上限的进度条 —— 一眼看出谁快超预算 |
| 时间信息 | 最近活动 · 创建 · 更新（点「更多」展开） |

支持按状态筛选、按列排序与过滤。

## 行内操作

| 操作 | 说明 |
|---|---|
| **查看** | 只读详情，分四组：基本信息 · 治理参数 · 速率限制 · 路由与标签 |
| **编辑** | 改作用域、限流、预算、过期时间 |
| **克隆** | 以现有密钥为模板颁发新密钥 —— 批量发同规格密钥时最省事 |
| **启用 / 禁用** | 立即生效；禁用后该密钥全部调用 401 |
| 复制令牌掩码 / 复制智能体 ID | 便于对账与排障 |
| **删除** | 二次确认；批量删除需输入 `DELETE` |
| **清理密钥** | 永久删除 N 天前所有**已吊销**的令牌，需填截止天数 |

批量操作：批量启用 / 禁用 / 删除。

## 密钥与智能体的绑定

绑定通常发生在**部署智能体**时 —— 部署向导的实例清单里每台机器都要选一个「网关密钥绑定」。部署页可选：

- **新建密钥** —— 部署时自动为该实例签发一把
- **使用已有密钥** —— 从**尚未绑定任何实例**的密钥里挑

绑定之后：

- VM 内的 agent 用这把密钥调用网关
- 计量中心能按智能体维度归集成本
- 密钥被禁用 / 超预算时只影响这一台

::: tip 一机一密钥
不要多台智能体共用一把密钥 —— 共用会让成本无法归属到具体的人，出问题时也没法精确止血。密钥不够就用「克隆」批量造。
:::

## 治理模板

| 场景 | 建议配置 |
|---|---|
| 试点验证 | 不设预算、不设过期、作用域全开，先跑通 |
| 按部门发放 | 标签标注部门；各设消费上限 + 预算周期按月；月度对账看[计量中心](/observability/metering)的按部门维度 |
| 外包 / 临时人员 | 有效时长 `30d` + 较低消费上限 + 作用域只给 `CHAT` + 限定单个路由 |
| 关键生产 agent | RPM/TPM 模式设保量；不设过期但设预算告警 |
| 高敏场景 | 开启自动轮换，周期缩到天级 |
| 人员离职 | 立即**禁用**（而不是删除），保留历史账单与审计关联；确认无需追溯后再删 |

## 出事时的止血顺序

<ol class="ap-steps">
<li><strong>禁用</strong>涉事密钥 —— 一秒生效，该实例的所有调用立刻 401。</li>
<li>到<a href="/observability/request-log">请求日志</a>按该智能体 ID 筛出全部调用，确认影响面。</li>
<li>到<a href="/observability/audit-log">审计日志</a>看这把密钥的签发 / 变更轨迹（动作：签发 / 吊销 / 启用禁用）。</li>
<li>确认无误后重新颁发一把新密钥，更新到 VM，再启用业务。</li>
</ol>

## 常见问题

| 现象 | 处理 |
|---|---|
| 调用返回 401 | 密钥被禁用 / 已过期 / 已吊销 / 超出消费上限；或请求的模型不在作用域内 |
| 调用返回 403 | 请求的**接口类型**不在 `可调用接口` 作用域内 |
| 调用返回 429 | 触发 RPM / TPM / 最大并发限制；调高限额、改限流模式或分散流量 |
| 忘记密钥明文 | 无法找回。删掉重发一把，或用「重新生成」换新密钥后更新到 VM |
| 消费进度一直是 0 | 该密钥没被真正使用，或模型未配置单价（成本算不出来） |
| 「可调用模型」下拉为空 | 还没选模型网关，或该网关下尚无路由 |
| 部署页「使用已有密钥」列表为空 | 已有密钥都绑定了实例；先克隆几把未绑定的出来 |
