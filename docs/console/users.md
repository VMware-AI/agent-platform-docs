# 用户与权限

> 系统配置 → 用户与权限 · 需要 <span class="ap-badge admin">admin</span>

管理平台用户、角色与权限分配，支持密码重置与角色绑定。页面有两个页签：**用户管理** 与 **角色与权限**。

## 用户管理

### 列表

| 列 | 说明 |
|---|---|
| 用户名 | 登录名 |
| 角色 | admin / read_only / user |
| 邮箱 | 联系邮箱 |
| 启用状态 | 已启用 / 已禁用 |
| 连接状态 | 在线 / 离线，可筛选 |
| 上次登录 | 最近一次登录时间 |
| 创建时间 · 更新时间 | 排序字段 |

排序支持：用户名 · 角色 · 邮箱 · 连接状态 · 上次登录 · 创建时间 · 更新时间。各列表头可搜索过滤，也可「清空」筛选。

### 新建用户

点 **新建用户**：

| 字段 | 说明 |
|---|---|
| 用户名 | 唯一；**输入时实时校验可用性**（「正在检查用户名可用性…」→「该用户名已被使用」） |
| 显示名 | 界面上展示的名字 |
| 邮箱 | 唯一，同样实时校验 |
| 角色 | 见下方角色说明 |
| 启用账户 | 取消勾选则创建后不可登录 |
| 密码类型 | **自动生成** 或 **自定义** |

**密码策略**（两种类型都要满足）：

| 规则 | 提示文案 |
|---|---|
| 长度 ≥ 12 | 长度至少 12 位 |
| 含大写字母 | 需含大写字母 |
| 含小写字母 | 需含小写字母 |
| 含数字 | 需含数字 |

表单会逐条实时提示未满足的规则；自定义模式下还会校验两次输入是否一致。

::: danger 自动生成的密码只显示一次
选「自动生成」时，界面提示「自动生成后通过一次性弹窗显示，注意复制保存！」。创建成功后弹窗展示初始密码，标题是「xxx 的初始密码」，并警告：

> 此密码仅显示一次，请立即复制并安全保存。关闭后无法再次查看。

关闭后只能走「重置密码」重新生成。
:::

### 行内操作

| 操作 | 说明 |
|---|---|
| **更换角色** | 改变该用户的平台角色，立即生效 |
| **重置密码** | 生成新的随机密码，同样只显示一次。确认提示「将为 xxx 生成新的随机密码，确认继续?」 |
| **禁用 / 启用** | 禁用后该用户无法登录。确认提示「禁用后，xxx 将无法登录。是否继续?」 |
| **删除** | 二次确认；最终确认需**输入用户名**；不可撤销 |

::: tip 离职处理用「禁用」而不是「删除」
禁用立即阻断登录，同时保留审计日志与历史归属关系 —— 三个月后要复盘「这个操作是谁做的」，删掉的用户就查不到名字了。确认无需追溯后再删。
:::

## 角色与权限

第二个页签展示平台内置角色，列：**角色名称 · 描述 · 用户数**。点某个角色可以查看**该角色下的用户**列表（用户名 / 邮箱 / 状态）。

### 三个内置角色

| 角色 | 定位 | 能做什么 |
|---|---|---|
| <span class="ap-badge admin">admin</span> 超级管理员 | 平台管理员 | 全量读写：资源池 / 网关接入、部署智能体、发密钥、管用户、看全部日志 |
| <span class="ap-badge readonly">read_only</span> 只读用户 | 观测岗 | 只读：计量中心、实时监控、请求日志、审计日志。**从不写** |
| `user` 普通用户 | 使用者 | 只读自己名下的资源 |

完整的权限点对照见 [角色与权限矩阵](/reference/roles)。

::: warning 页面按角色裁剪
非 admin 用户访问系统配置类页面会被**重定向到总览**。这是刻意设计：与其让页面加载后每个请求都报权限错误，不如提前拦住。
:::

## 该给谁什么角色

| 人 | 角色 | 理由 |
|---|---|---|
| 平台运维、部署负责人 | `admin` | 需要接入底座、部署实例、发密钥 |
| 安全 / 合规 / 财务对账 | `read_only` | 需要看审计与账单，但绝不应改配置 |
| 智能体使用者 | `user` | 只需看自己那台机器；日常操作都在 VM 管理台完成 |

::: danger admin 账号要收敛
admin 可以删除资源池、彻底删除实例、吊销全部密钥 —— 任何一项都是全局性的破坏。建议只给必要的少数人，并靠[审计日志](/observability/audit-log)追踪其操作。

给「想看数据的领导」发 admin 是最常见的错误，`read_only` 才是那个位置该给的角色。
:::

## 账号治理建议

<ol class="ap-steps">
<li><strong>装完立刻改掉 bootstrap 管理员密码</strong>（默认 <code>ChangeMe123!</code>）。</li>
<li><strong>给自己建一个具名 admin 账号</strong>，日常用它操作 —— 审计日志里才能看出是谁干的，而不是永远显示那个共享的 <code>admin@platform.local</code>。</li>
<li><strong>观测岗一律 <code>read_only</code></strong>。</li>
<li><strong>定期看「上次登录」</strong>，长期不登录的账号先禁用。</li>
<li><strong>人员变动当天处理</strong>：禁用账号 → 禁用其智能体绑定的密钥 → 回收实例。</li>
</ol>

## 个人资料与改密

任何登录用户都能从右上角用户菜单进入**个人资料**，查看：

| 分组 | 字段 |
|---|---|
| 账户身份 | 用户名、显示名、邮箱、角色 |
| 账号元数据 | 账户创建时间、最后登录时间、连接状态、是否需要修改密码 |

点 **修改密码** 打开对话框：当前密码 + 新密码 + 确认新密码，密码框可切换显示 / 隐藏。

如果账户被标记为「需要修改密码」（例如管理员刚重置过、或首次使用 bootstrap 口令登录），登录后会**强制弹出**改密对话框，提示「为了您的账户安全，请设置一个新的登录密码」，完成前无法进行其他操作。

## 常见问题

| 现象 | 处理 |
|---|---|
| 用户名 / 邮箱提示已被使用 | 换一个；系统输入时就在实时校验 |
| 新建用户后对方登录失败 | 确认「启用状态」为已启用；确认密码复制完整（首尾空格是常见坑） |
| 用户看不到某个页面 | 角色权限所限，见[角色与权限矩阵](/reference/roles) |
| 忘记初始密码 | 走「重置密码」重新生成 |
| 改密码提示两次不一致 | 新密码与确认框不一致 |
| 想给用户只开放某几个页面 | 当前只有三个内置角色，粒度到角色为止；更细的授权需求请反馈 |
| 审计日志里全是同一个 admin | 说明大家在共用 bootstrap 账号 —— 给每人建具名 admin |
