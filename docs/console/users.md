# 用户与权限

> 系统配置 → 用户与权限 · 需要 <span class="ap-badge admin">admin</span>

管理平台用户、角色与权限分配，支持密码重置与角色绑定。页面有两个页签：**用户管理** 与 **角色与权限**。

## 用户管理

### 列表

| 列 | 说明 |
|---|---|
| 用户名 | 登录名 |
| 角色 | admin / read_only / user |
| 邮箱 | 联系邮箱 |
| 启用状态 | 已启用 / 已禁用 |
| 连接状态 | 在线 / 离线，可筛选 |
| 上次登录 · 创建时间 · 更新时间 | 排序字段 |

### 新建用户

点 **新建用户**：

| 字段 | 说明 |
|---|---|
| 用户名 | 唯一；输入时实时校验可用性 |
| 显示名 | 界面上展示的名字 |
| 邮箱 | 唯一；同样实时校验 |
| 角色 | 见下方角色说明 |
| 启用账户 | 取消勾选则创建后不可登录 |
| 密码类型 | **自动生成** 或 **自定义** |

**密码要求**：长度 ≥ 12，且含大写字母、小写字母、数字。表单会逐条提示未满足的规则。

::: danger 自动生成的密码只显示一次
选择「自动生成」后，创建成功会弹出一次性对话框展示初始密码。**关闭后无法再次查看**，请立即复制并安全地交给用户。忘了只能走「重置密码」。
:::

### 行内操作

| 操作 | 说明 |
|---|---|
| 更换角色 | 改变该用户的平台角色 |
| 重置密码 | 生成新的随机密码，同样只显示一次 |
| 禁用 / 启用 | 禁用后该用户无法登录，但历史记录保留 |
| 删除 | 二次确认，最终确认需**输入用户名**；不可撤销 |

::: tip 离职处理用「禁用」而不是「删除」
禁用立即阻断登录，同时保留审计日志与历史归属关系。确认无需追溯后再删除。
:::

## 角色与权限

第二个页签展示平台内置角色：角色名称、描述、用户数。点某个角色可以查看**该角色下的用户**列表。

### 三个内置角色

| 角色 | 定位 | 能做什么 |
|---|---|---|
| <span class="ap-badge admin">admin</span> 超级管理员 | 平台管理员 | 全量读写：资源池 / 网关接入、部署智能体、发密钥、管用户、看全部日志 |
| <span class="ap-badge readonly">read_only</span> 只读用户 | 观测岗 | 只读：计量中心、实时监控、请求日志、审计日志。**从不写** |
| `user` 普通用户 | 使用者 | 只读自己名下的资源 |

完整的权限点对照见 [角色与权限矩阵](/reference/roles)。

::: warning 页面按角色裁剪
非 admin 用户访问系统配置类页面会被弹回总览 —— 这是刻意设计：与其让页面加载后每个请求都报权限错误，不如提前拦住。
:::

## 个人资料与改密

任何登录用户都可以从右上角用户菜单进入**个人资料**，查看：

- 账户身份：用户名、显示名、邮箱、角色
- 账号元数据：创建时间、最后登录时间、连接状态、是否需要修改密码

点 **修改密码** 打开对话框，需要填当前密码 + 新密码 + 确认新密码。

如果账户被标记为「需要修改密码」（例如管理员刚重置过），登录后会强制弹出改密对话框，完成前无法进行其他操作。

## 常见问题

| 现象 | 处理 |
|---|---|
| 用户名 / 邮箱提示已被使用 | 换一个；系统在输入时就会实时校验 |
| 新建用户后对方登录失败 | 确认「启用状态」为已启用；确认密码复制完整 |
| 用户看不到某个页面 | 角色权限所限，见[角色与权限矩阵](/reference/roles) |
| 忘记初始密码 | 走「重置密码」重新生成 |
