# 技能管理

> 智能体中心 → 技能管理 · 需要 <span class="ap-badge admin">admin</span>

统一管理 OpenClaw、OpenCode、Hermes 等智能体可使用的技能与能力扩展。

**技能的分发模型是「离线优先」**：包先进跳板机的离线仓库，智能体 VM 再从内网仓库拉取安装。全程不需要 VM 有外网。

```
上游包源 ──(在线下载, 后端发起)──┐
                                ├──▶ 跳板机离线仓库 ──▶ Agent VM 安装
本地 .tar.gz ──(上传, 浏览器)────┘
```

## 页面结构

顶部统计：**总技能** · **当前显示** · **已选中**。

工具栏：按分类筛选、按状态筛选、关键字搜索、**刷新**、**新增 Skill**。

列表列：Skill · 描述 · 分类 · Agent · 版本 · 安装方式 · 状态 · 操作。

| 维度 | 取值 |
|---|---|
| 分类 | 开发 · 运维 · 办公 · 安全 · 数据 · AI |
| 状态 | 已启用 / 已停用 |
| 安装方式 | Python 包（pip）· NPM 包 · 二进制程序 |

## 新增 Skill

点 **新增 Skill**，表单分四段。

### 一、基础信息

| 字段 | 说明 |
|---|---|
| Skill 标识 | **仅小写字母、数字和短横线**，创建后不可修改 |
| Skill 名称 | 显示名 |
| 描述 | 用途说明 |
| 分类 | 开发 / 运维 / 办公 / 安全 / 数据 / AI |
| 适用 Agent | 该技能可安装到哪些 agent 类型（可多选，或「全部」） |

::: warning 标识定了就改不了
`Skill 标识` 是不可变主键。想改只能删除重建 —— 建之前先想好命名规范，例如 `vmware-ops`、`jira-cli`、`sql-lint`。
:::

### 二、安装信息

| 字段 | 说明 |
|---|---|
| 安装方式 | pip / npm / 二进制 |
| 源包 URL | 上游包地址 |
| 版本 | 包版本 |

### 三、离线包部署（关键）

这一段决定 VM 能不能真的装上。

| 字段 | 说明 |
|---|---|
| 离线仓库地址 | Agent VM 通过此地址下载离线包。同步 / 上传后的包会存到这里 |
| 离线包 URL | 仓库中的实际包地址 |
| 本地上传 | 选择本地 `.tar.gz` 上传到跳板机 |

两种入库方式：

| 方式 | 操作 | 网络要求 |
|---|---|---|
| **在线下载** | 填源包 URL → 点「在线下载」 | **后端**（不是 VM）需要能访问该 URL |
| **上传到离线库** | 选本地 `.tar.gz` → 点「上传到离线库」 | 只需要浏览器能到控制台 |

表单会给出就绪状态：

- ✓ **离线包已就绪：`<url>`**
- ⚠ **离线包尚未同步到跳板机，部署时无法安装**

::: danger 没入库就等于装不上
只填了源包 URL、没执行「在线下载」或「上传」，包并不在跳板机上，安装到 VM 必然失败。**发布前一定要看到绿色的「✓ 离线包已就绪」。**
:::

::: tip 气隙环境用「上传」
完全离网时后端也访问不了公网，「在线下载」用不了。正确姿势是：在有网的机器上把包下下来 → 拷进内网 → 用「本地上传」入库。
:::

### 四、MCP 配置（可选）

需要以 MCP Server 形式暴露的技能在这里配置。

### 直接装到某台机器

表单里还有一个 **Agent IP 地址** 字段：填已运行 agent 的 IP，后端会自动 SSH 过去安装离线包。适合单台验证。

## 安装到智能体

两个入口，效果相同：

- **技能管理页** → 某个 Skill 的「安装到 Agent」
- **[智能体实例](/console/agents)页** → 某台实例的「安装 Skill」

安装对话框的流程：

<ol class="ap-steps">
<li>列出<strong>离线包</strong>清单（显示「离线包 N 个」），可按 agent 类型过滤、分页浏览。</li>
<li>自动检查每个包在该 agent 上的状态 —— 「正在检查已安装状态...」→ <strong>已安装</strong> / <strong>未安装</strong>。</li>
<li>勾选要装的，点「安装 N 个 Skill」。</li>
<li>完成后汇总「安装完成: N/M 成功」。</li>
</ol>

::: tip 对话框提示「暂无可用离线 Skill」
说明离线库里还没有任何已就绪的包，提示语会引导你「请先在技能管理中同步离线包」。
:::

## 其他操作

| 操作 | 说明 |
|---|---|
| 编辑 | 改名称、描述、分类、适用 Agent、安装信息（标识不可改） |
| 删除 | 从平台移除该技能登记（不会卸载已装到 VM 上的） |
| 刷新 / 重新加载 | 重新拉取列表 |
| 清除筛选条件 | 一键复位 |

## 技能 vs 知识包

两个都是「给 agent 补充能力」，但不是一回事：

| | 技能 Skill | [知识包](/guide/concepts#知识包-knowledge-pack) |
|---|---|---|
| 是什么 | 可执行的能力扩展（pip / npm / 二进制，可带 MCP） | 离线知识资料包 |
| 怎么下发 | 控制台触发，SSH 安装到指定 VM | 挂在智能体配置上，随心跳自动同步 |
| 何时生效 | 安装完立即 | 下次心跳 |
| 校验 | 包本身的安装过程 | sha256 三重校验 + 防路径穿越解压 |
| 失败影响 | 该次安装失败 | best-effort 降级，**绝不影响心跳** |

## 常见问题

| 现象 | 处理 |
|---|---|
| 安装失败 | ① 离线包是否已就绪 ② agent VM 能否访问「离线仓库地址」 ③ 目标 agent 类型是否在「适用 Agent」里 |
| 在线下载失败 | 后端需要能访问源包 URL；离网环境改用本地上传 |
| 列表为空 | 还没创建任何 Skill，或筛选过窄 —— 点「清除筛选条件」 |
| 标识填错了 | 不可修改，只能删除重建 |
| 装完 agent 里没生效 | 部分技能需要重启 agent 进程才加载；SSH 进去确认包确实装上了 |
| 想给一批机器批量装 | 逐台走安装对话框；或在实例列表里逐台点「安装 Skill」 |
