# 部署智能体

> 智能体市场 → 卡片上的「部署智能体」 · 需要 <span class="ap-badge admin">admin</span>

部署向导把「一台或一批智能体虚拟机」拆成四段：**基础运行环境 → 全局安全与认证 → 部署模式与网络 → 实例配置清单**。前三段是所有实例共享的，最后一段逐台确定。

## 开始之前

确认这四样都就绪，否则向导里会出现空下拉：

| 前置 | 检查点 |
|---|---|
| 资源池已同步 | [资源池接入](/console/resource-pools)里状态为「已同步」，资产能看到集群 / 网络 / 数据存储 |
| 模板族有版本 | [智能体市场](/console/marketplace)里卡片显示版本号 |
| 网关已接入 | [模型网关接入](/console/gateway-connections)状态正常，且 **Agent 访问地址填对** |
| 密钥够用 | [密钥管理](/console/keys)里有未绑定实例的密钥，或用部署时新建 |

## 一、基础运行环境

所有实例共享的底层 IaaS 资源配置。

| 字段 | 说明 |
|---|---|
| 选择版本 | 模板族下的具体版本，默认最新 |
| vSphere 放置资源池 | VM 放在哪个 vSphere 资源池。留空 = 继承源模板所在池 |
| 目标端口组 | VM 网卡接哪个端口组。留空 = 继承源模板网卡 |
| 目标数据存储 | 默认 `vsanDatastore` |
| 克隆模式 | **全量克隆** 或 **即时克隆** |

### 全量克隆 vs 即时克隆

| | 全量克隆 `full` | 即时克隆 `instant` |
|---|---|---|
| 速度 | 分钟级 | **秒级** |
| 需要父虚拟机 | 否 | **是** |
| 磁盘占用 | 独立完整副本（vSAN 去重后实际占用远小于名义值） | 初期共享父机内存与磁盘页 |
| 后续生命周期 | 完全独立 | **完全独立** |
| 适用 | 少量、常规部署 | 大批量快速交付 |

选择即时克隆后需要指定父虚拟机，有两条路径：

- **选择已有父虚拟机** —— 从下拉里挑（后端会列出可用的父机）
- **创建新父虚拟机** —— 填名称与静态 IP，可添加多个（大批量时用多个父机分摊负载）

::: tip 即时克隆不影响独立性
克隆出来的 VM 是完全独立的 vCenter 清单对象，可以像常规虚拟机一样管理 —— 快照、vMotion、改配都不受影响。即时克隆只影响**创建速度**，不影响后续生命周期与数据持久性。界面上也有这句提示。
:::

## 二、全局安全与认证

所有实例统一的 Cloud-Init / vApp 系统凭据。

| 字段 | 说明 |
|---|---|
| 密码 / 确认密码 | VM 的 OS 登录密码，两次必须一致 |
| SSH 公钥（可选） | 注入到 VM，便于免密登录 |

::: danger 平台不存储明文密码
密码经 guestinfo / vApp 属性注入 VM，平台侧**不保存明文**，界面上只有「密码由部署时设定，平台不存储明文」的提示。遗忘只能：

1. 让使用者在 [VM 自服务管理台](/agent-vm/webadmin) 自行修改（需要知道旧密码）
2. 通过 vCenter Console 重置
3. 在实例的[快捷运维操作](/console/agents#快捷运维操作)里触发「密码更新」
:::

::: tip 批量部署时的密码策略
一批 VM 共用同一个初始密码，交付时务必要求使用者**首次登录立即改密**。管理台的改密是 OS + Web 同步事务，改一次两边都变，成本很低。
:::

## 三、部署模式与网络策略

### 部署模式

| 模式 | 填什么 |
|---|---|
| **单台部署** | 一台的名称与网络 |
| **批量部署** | 名称前缀、数量、起始 IP，点「生成清单」自动展开 |

### 网络策略

| 模式 | 需要填 |
|---|---|
| DHCP | 无 |
| 静态 IP | 起始 IP、子网掩码、网关、DNS（逗号分隔多个） |

批量 + 静态 IP 时，从「起始 IP」开始按数量顺序递增分配。

::: danger 静态 IP 冲突是部署卡住的头号原因
生成清单后**逐行核对 IP 是否与现网冲突**。冲突的 VM 会开机成功但拿不到网络，实例长时间停在「部署中」直至转「异常」，而 vCenter 侧看起来一切正常 —— 这种故障最费时间。

批量前先在目标网段扫一遍：`nmap -sn 192.168.10.0/24`。
:::

## 四、实例配置清单

生成的表格逐行确认：

| 列 | 说明 |
|---|---|
| 主机名 | 由名称前缀 + 序号生成，可逐行改 |
| IP 地址 | 静态模式下按起始 IP 递增；DHCP 模式为空 |
| 密钥绑定 | **每台选一个虚拟密钥** |

密钥绑定有两种来源：

- **新建密钥** —— 部署时自动为该实例签发一把
- **使用已有密钥** —— 从**尚未绑定任何实例**的密钥里挑

::: tip 一机一密钥
每台实例绑独立密钥，这样[计量中心](/observability/metering)能按智能体归集成本，出问题也能单独禁用止血。密钥不够就先去[密钥管理](/console/keys)用「克隆」批量造几把。
:::

其他可选项：**部署说明（notes）**、**预算上限**、**自定义 OVF 属性**。

确认无误后点 **部署**。

## 部署过程中发生了什么

```
控制台 ──▶ backend ──(govmomi)──▶ vCenter
   ① clone -on=false                    从内容库 OVA 模板克隆，先不开机
   ② 注入 guestinfo（gzip + base64）      OS 凭据、SSH 公钥、网关 Agent 访问地址、
                                          虚拟密钥、知识包授权列表、网络配置
   ③ power on                            开机
   ④ 等待 VM 上报 IP
   ⑤ 任一步失败 → vm.destroy 回滚         不留半成品

VM 侧：cloud-init 渲染配置 → agent-manager enroll 注册（一次性 token 换长期 token）
        → 周期心跳（上报状态 + 真实已装版本）
控制台：状态「部署中」→「运行中」
```

单台通常 **5–10 分钟**完成。批量部署各实例**独立推进**，部分失败不影响其余。

::: tip 失败会自动回滚
任一步失败后端会执行 `vm.destroy`，不会在 vCenter 里留下半成品 VM。所以看到 vCenter 里没有那台机器，说明它确实失败了 —— 去审计日志看原因。
:::

## 部署后

<ol class="ap-steps">
<li>到<a href="/console/agents">智能体实例</a>列表确认状态为「运行中」。</li>
<li>点该实例的 <strong>访问信息</strong>，「一键复制全部凭据」。</li>
<li>把 IP、SSH 命令、OS 账户与密码、管理台地址 <code>https://&lt;VM_IP&gt;/manage/</code> 发给使用者。</li>
<li>需要的话在<a href="/console/skills">技能管理</a>里给这台机器安装 Skill。</li>

</ol>

## 常见问题

| 现象 | 排查 |
|---|---|
| 下拉（资源池 / 端口组 / 数据存储）为空 | 资源池尚未同步资产，回[资源池接入](/console/resource-pools)点「立即同步」 |
| 「网关密钥绑定」的已有密钥列表为空 | 现有密钥都绑了实例；克隆几把未绑定的，或改用「新建密钥」 |
| 即时克隆的「父虚拟机」下拉为空 | 该资源池上没有可用父机；改用「创建新父虚拟机」 |
| 部署立即失败 | 查[审计日志](/observability/audit-log)（类别=智能体，动作=部署，结果=失败）：vCenter 权限不足、名称冲突、数据存储空间不足 |
| 长时间停在「部署中」 | ① VM 有没有拿到 IP（静态 IP 配错最常见）② VM 能否出站访问控制面 443 ③ vCenter Console 里看 VM 是否真的起来了 |
| 起来了但状态是「异常」 | 心跳没通。VM 内 `systemctl status agent-manager`，看 `journalctl -u agent-manager` |
| 批量部署部分失败 | 失败的删除后重试即可，成功的不受影响 |
| 部署成功但 agent 调不通模型 | 九成是网关的「Agent 访问地址」填成了控制面内部地址 |
