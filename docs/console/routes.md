# 网关路由

> 模型调度台 → 网关路由 · 需要 <span class="ap-badge admin">admin</span>

管理网关上的路由清单：一条路由 = 一个对外的逻辑模型名 + 一组底层供应商模型 + 一套分派策略 + 降级链。智能体调用时用的是**路由名**，不是上游模型原名。

## 新建路由

点 **新建路由**：

| 字段 | 说明 |
|---|---|
| 路由名称 | 大写字母、数字与中划线，2–64 字符。这就是智能体请求里写的模型名 |
| 模型网关 | 该路由归属的网关 |
| 路由策略 | 见下表 |
| 选择路由的模型 | 左「可选模型列表」→ 右「已选定的模型」的穿梭框 |

::: tip 下拉为空
「可选模型列表」为空说明还没选网关，或该网关下尚无可用模型。先去[模型管理](/console/models)登记。
:::

## 路由策略

| 策略 | 行为 | 适用 |
|---|---|---|
| 简单洗牌 SIMPLE_SHUFFLE | 随机分流 | 多个同质实例，最省心 |
| 最闲优先 LEAST_BUSY | 选当前并发最少的 | 长请求、并发波动大 |
| 延迟优先 LATENCY_BASED_ROUTING | 选历史延迟最低的 | 对响应时间敏感 |
| 使用率优先 USAGE_BASED_ROUTING_V2 | 按用量均衡 | 多实例配额均摊 |
| 成本优先 COST_BASED_ROUTING | 选单价最低的 | 成本敏感、质量差异可接受 |

## 降级链（高级参数）

展开「高级参数」可配置三类降级目标，每类都是一个**有序的路由列表**：

| 降级类型 | 触发条件 | 典型配置 |
|---|---|---|
| 常规故障转移 | 任何网络错误或限流时按顺序顺延 | 主模型 → 备用模型 |
| 上下文超限降级 | 超出模型最大 token 时 | 小上下文模型 → 大上下文模型 |
| 内容策略降级 | 触发内容审查时 | 严格模型 → 更宽松的模型 |

::: warning 降级目标是路由，不是模型
下拉里列的是**其他路由**。如果提示「暂无可作为降级目标的路由」，说明该网关下只有当前这一条路由，先建第二条。
:::

## 列表与操作

| 列 | 说明 |
|---|---|
| 路由名称 | 智能体调用时使用的模型名 |
| 模型网关 | 归属网关 |
| 路由策略 | 当前策略 |
| 网关模型 | 该路由挂载的模型列表 |
| 创建 / 更新时间 | 排序字段 |

行内操作：**编辑**、**管理**。工具栏：**同步路由**、**刷新**、**批量删除**。

::: tip 同步路由
改完路由后如果网关侧没立即生效，点「同步路由」把平台侧配置推送到网关。
:::

## 一条路由的生命周期示例

<ol class="ap-steps">
<li>建两条模型登记：<code>qwen-72b-a</code>（主机房）、<code>qwen-72b-b</code>（备机房），都指向同一个上游模型原名。</li>
<li>新建路由 <code>QWEN-72B</code>，策略选「最闲优先」，把两条模型都挑进已选定列表。</li>
<li>再建一条路由 <code>QWEN-32B</code> 作为降级目标。</li>
<li>回到 <code>QWEN-72B</code> 编辑 → 高级参数 → 常规故障转移选 <code>QWEN-32B</code>。</li>
<li>颁发虚拟密钥时把可调用模型限定为 <code>QWEN-72B</code>。</li>
<li>智能体请求 <code>model: "QWEN-72B"</code>，网关按策略分派，失败时自动降级。</li>
</ol>

## 常见问题

| 现象 | 处理 |
|---|---|
| 智能体报「模型不存在」 | 请求里写的是上游模型原名而不是路由名；或该密钥的作用域不含这条路由 |
| 配好降级链但没生效 | 确认降级目标路由本身是健康的；点「同步路由」重推一次 |
| 路由挂的模型全被熔断 | 调用会失败并走降级链；去[模型管理](/console/models)解除熔断 |
