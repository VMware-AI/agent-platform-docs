# 模型管理

> 模型调度台 → 模型管理 · 需要 <span class="ap-badge admin">admin</span>

管理上游供应商提供的模型配置（鉴权、速率与计费参数），控制平台侧的接入门禁与健康探测。

## 两层结构

平台把「一个逻辑模型」和「它背后的物理上游」分成两层：

```
模型 ProviderModel                    ← 平台侧一条登记，必须归属一个模型网关
  ├─ 名称 / 网关 / 组织
  └─ 供应商模型规格 ModelSpec ×N       ← 同名模型的多个上游实例
       litellmParams: 上游模型原名 · API Base · API Key · 供应商 · 限流 · 单价 · 标签
       modelInfo:     模型模式 · 是否熔断 · 健康状态
```

一条模型下挂多个 spec，就能把同一个逻辑模型指向多个上游端点（不同机房、不同实例、不同厂商），由网关按路由策略分派、按健康状态摘除。

::: tip 三个「模型」不要混
- **上游模型原名**（`litellmParams.model`）—— 厂商侧的真名，如 `gpt-4o-mini`
- **模型名称**（`ProviderModel.name`）—— 平台里的登记名，路由挑选时看到的
- **路由名**（[网关路由](/console/routes)的 `name`）—— 智能体请求里真正要写的那个

智能体请求里写错成前两者，会直接报「模型不存在」。
:::

## 新建模型

点 **新建模型**，向导三步，右上角有步骤指示（`第 N 步 / 共 3 步`）。

<ol class="ap-steps">
<li><strong>基本</strong> —— 模型名称、所属模型网关、所属组织。</li>
<li><strong>供应商模型</strong> —— 添加一个或多个 spec，逐个可「测试连接」。</li>
<li><strong>确认并提交</strong> —— 复核全部字段，包括 API Key 是「已设置新密钥 / 保持原密钥 / 将轮换为新密钥」三态之一。</li>
</ol>

### 第一步：基本

| 字段 | 约束 | 说明 |
|---|---|---|
| 模型名称 | 大小写字母、数字、中划线与点，2–64 字符 | **编辑时不可更改** |
| 模型网关 | 必填 | 该模型推送到哪个网关 |
| 所属组织 | 行级字段 | **编辑模式下不可改** |

### 第二步：供应商模型（spec）

一个 spec 描述一个真实上游端点。

**必填三项**

| 字段 | 说明 |
|---|---|
| 上游模型原名 | 供应商侧的真实模型名，如 `deepseek-chat`、`Qwen2.5-72B-Instruct` |
| API Base | 上游服务地址。内网私有模型服务也填这里 |
| API Key | **后端加密入库，前端永不回显** |

**供应商分类**（`customLlmProvider`，默认 `openai`）

| 取值 | 适用 |
|---|---|
| `custom` | 任意 OpenAI 兼容端点 —— 内网 vLLM / Ollama / 自建推理服务常用 |
| `openai` | OpenAI |
| `anthropic` | Anthropic |
| `deepseek` | DeepSeek |
| `minimax` | MiniMax |
| `moonshot` | Moonshot（月之暗面） |
| `openrouter` | OpenRouter（多模型聚合） |

::: tip 内网自建模型选哪个
绝大多数内网推理服务（vLLM、SGLang、Xinference、Ollama）都提供 OpenAI 兼容接口，选 `custom` 并把 API Base 指向它即可。
:::

**限流与预算**

| 字段 | 说明 |
|---|---|
| TPM / RPM | 该 spec 的每分钟 Token 数 / 请求数上限 |
| 默认密钥 TPM / RPM 限制 | 由此 spec 派生的密钥的默认限额 |
| 消费上限 / 预算周期 | spec 级别的花费封顶与重置周期 |

平台侧的「限制类型」有三档：Token 限制 / 请求数限制 / 组合限制。

**计费单价** —— 计量中心的成本估算完全依赖这四个字段：

| 字段 | 含义 |
|---|---|
| 输入单价（`inputCostPerToken`） | 每个输入 token 的价格 |
| 输出单价（`outputCostPerToken`） | 每个输出 token 的价格 |
| 缓存读取单价（`cacheReadInputTokenCost`） | 命中缓存的输入 token 价格 |
| 缓存写入单价（`cacheCreationInputTokenCost`） | 写入缓存的 token 价格 |

::: danger 不填单价 = 算不出钱
仪表盘的「本月费用」、计量中心的成本估算、密钥的消费进度，全都建立在这几个单价上。缺价格时的行为可在[计量设置](/observability/metering-settings)里选：标记为待配置 / 按 0 计算并告警 / 拒绝生成费用记录。缓存单价是否参与计算也在那里开关。
:::

**高级开关**

| 开关 | 说明 |
|---|---|
| 直通模式（`useInPassThrough`） | 请求原样透传给上游，不做协议改写 |
| 使用 chat/completions（`useChatCompletionsApi`） | 强制走 chat completions 接口 |
| 合并 reasoning 内容（`mergeReasoningContentInChoices`） | 把推理链内容并入返回的 choices |
| 模型模式（`mode`） | chat / embedding / image 等用途标记 |
| 标签（`tags`） | 逗号分隔，用于分组与路由筛选 |

### 第三步：确认并提交

复核页会逐项列出基本信息与每个 spec（`模型 #1`、`模型 #2`…），并明确标注 API Key 的处置方式，避免误轮换。

## 健康状态

平台按 `PROVIDER_PROBE_INTERVAL_SECONDS` 周期探测每个 spec，并把结果汇总到模型级别：

| 模型级状态 | 后端枚举 | 含义 | 是否还能服务 |
|---|---|---|---|
| **健康** | `full_healthy` | 全部 spec 探测通过 | 是 |
| **降级** | `partial_outage` | 至少 1 个健康 + 至少 1 个异常 | 是（流量转到健康的 spec） |
| **熔断** | `full_outage` | 全部 spec 异常并进入冷却 | **否，拦截新请求** |
| **未探测** | `unknown` | 全部 spec 的探测结果已超时 | 未知 |

单个 spec 的健康是 `healthy` / `unhealthy` / `unknown` 三态，异常时会携带错误信息，鼠标悬停可见。列表还会显示 `lastCheckedAt`（「X 分钟前检查」）。

行内操作：**探测**、**检测健康**、**熔断**（手工摘除某个 spec）、**解除熔断**。

::: warning 熔断是保护，不会自动恢复
`full_outage` 会拦截新请求并让路由走[降级链](/console/routes#降级链)。上游修好后必须**手工点「解除熔断」**。手工熔断也一样 —— 它是给「已知上游要维护」准备的开关。
:::

## 列表与批量操作

| 能力 | 说明 |
|---|---|
| 筛选 | 按状态（全部 / 启用 / 未启用）、按模型网关 |
| 排序 / 过滤 | 各列表头 |
| 行内操作 | 探测 · 检测健康 · 编辑 · 应用至… · 启用 · 禁用 · 删除 · **管理供应商模型** |
| 批量 | 批量启用 · 批量禁用 · 批量删除（未选中时按钮禁用） |

- **管理供应商模型** 打开抽屉，在里面增删改该模型下的 spec 列表。
- **应用至…** 把当前模型的配置套用到其他目标，适合一批同规格模型的批量调参。

## 典型配置示例

**内网 vLLM 单实例**

```
模型名称        qwen2.5-72b
模型网关        内网 LiteLLM
供应商分类      custom
上游模型原名    Qwen2.5-72B-Instruct
API Base       http://10.20.1.15:8000/v1
API Key        （内网服务无鉴权时填占位串）
TPM / RPM      按压测结果填
输入/输出单价   按内部核算价填，否则算不出成本
```

**同一模型双机房容灾**

建一条模型 `qwen2.5-72b`，挂两个 spec：`http://bj.llm:8000/v1` 与 `http://sh.llm:8000/v1`。任一机房挂掉，模型转「降级」而不是「熔断」，流量自动落到活着的那个。

## 常见问题

| 现象 | 处理 |
|---|---|
| 测试连接失败 | API Base 控制面是否可达；API Key 是否有效；供应商分类是否与上游协议匹配 |
| 保存后一直「未探测」 | 点「检测健康」主动触发；确认探测周期未被调得过长 |
| 编辑时看不到 API Key | 正常，加密入库不回显。留空 = 保持原密钥 |
| 模型「熔断」但上游明明是好的 | 探测路径与业务路径可能不同（如探测走的 API Base 有防火墙）；确认后手工解除熔断 |
| 计量里这个模型没有费用 | 单价未配置 |
| 改了名称却保存不了 | 模型名称创建后不可更改，需新建 |
