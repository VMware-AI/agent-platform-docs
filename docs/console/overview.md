# 总览仪表盘

登录后的首页，一屏回答四个问题：**平台健不健康、智能体在不在跑、调用质量如何、这个月花了多少钱。**

右上角提供**刷新**与**自动刷新**开关，并显示「最新刷新时间」。

## 顶部 KPI 卡

| 卡片 | 含义 | 点击 |
|---|---|---|
| 平台健康度 | 正常 / 存在警告 / 部分异常 / 严重异常，附严重与警告计数 | — |
| 活跃智能体 | 运行中实例数 / 智能体池总数 | 智能体实例 |
| 接入模型 | 健康模型数 / 模型总数 | 模型管理 |
| 总请求量 | 统计窗内的调用总数（已剔除重复） | 请求日志 |
| P95 响应时间 | 95 分位延迟，附平均延迟 | 实时监控 |
| 本月费用 | 当月累计与预计月底费用 | 计量中心 |

## 后端汇总了什么

仪表盘的数据来自一次聚合查询，口径固定：

| 指标 | 说明 |
|---|---|
| 智能体总数 / 运行中 / 已停止 / 异常 | 实例状态分布 |
| 虚拟密钥总数 | 已颁发的密钥数 |
| 网关总数 · 资源池总数 · 用户总数 | 平台规模 |
| 本月调用次数 · 本月 Token · 本月费用 | 当月累计 |

最近运行列表默认取 **5 条**，系统通知默认取 **5 条**。

## 主要区块

### 平台组件健康

后端服务、网关、数据库等组件的实时状态，附「平台最近检查时间」。任一组件异常，顶部健康度同步下降。

| 组件状态 | 含义 |
|---|---|
| 正常 | 全绿 |
| 存在警告 | 有非致命告警 |
| 部分异常 | 部分组件不可用 |
| 严重异常 | 关键组件挂了 |

### 实例状态分布与健康度趋势

环图按**运行中 / 已停止 / 异常 / 已回收**分布，配一条健康度趋势线。

### 调用质量

统计窗内的成功率、错误率与延迟走势。异常升高时的排查路径：**这里看到拐点 → [请求日志](/observability/request-log)按该时间窗 + 状态码筛 → 定位到具体模型或智能体**。

### 最近智能体运行

最近的调用记录表：智能体、模型、Token、延迟、状态、时间。点「查看全部请求日志」进入完整视图。

### 本月用量摘要

- 当月累计花费与**预计月底费用**
- 较上月变化
- **最高消耗智能体**

预测口径在[计量设置](/observability/metering-settings)里切换（当月日均线性 / 最近 7 天日均 / 不显示）。

### 异常与待处理事项

聚合当前需要人工处理的项，按严重程度分成成功 / 警告 / 危险三档。典型内容：

- 状态为「异常」的实例
- 被熔断的模型
- 即将过期或已超预算的密钥
- 缺单价、缺汇率的告警（在[计量设置](/observability/metering-settings)里开关）

无事项时显示「当前暂无待处理异常」。

::: tip 把这一块当每日巡检清单
每天上班先看这里。空的就是没事；有条目就点进去处理掉。比逐页翻要快得多。
:::

### 快捷入口

一行直达：智能体列表 · 模型管理 · 实时监控 · 请求日志 · 计量中心 · 审计日志。

## 谁能看到

所有已登录用户都能进入总览，但**内容按角色裁剪**：

| 角色 | 看到什么 |
|---|---|
| <span class="ap-badge admin">admin</span> | 全部 |
| <span class="ap-badge readonly">read_only</span> | 全部只读指标 |
| `user` | 仅与自己相关的部分 |

## 新装之后这一页是空的

刚装完平台，几乎所有卡片都是 0 —— 因为还没接入资源池、网关，也没部署任何智能体。按 [初始化四步走](/console/bootstrap) 走一遍，数据自然就有了。

## 常见问题

| 现象 | 处理 |
|---|---|
| 全是 0 | 新装状态，先做[初始化](/console/bootstrap) |
| 本月费用为 0 但有调用 | 模型没配单价 → [模型管理](/console/models) |
| 健康度「严重异常」 | 看「平台组件健康」哪个红了，再去 [健康检查](/install/verify) 逐项验证 |
| 活跃智能体数比预期少 | 有实例转成了「已停止」或「异常」，点进智能体实例看 |
| 数据不刷新 | 打开右上角自动刷新，或手动点刷新；确认「最新刷新时间」在走 |
