# 模型网关接入

> 系统配置 → 模型网关接入 · 需要 <span class="ap-badge admin">admin</span>

配置并管理 **LiteLLM** 等大模型网关的接入。所有模型调用都经由网关代理 —— 这是平台做限流、预算、审计与计量的挂钩点。**不接网关，模型 / 密钥 / 路由三页全是空的。**

## 接入一个网关

点 **接入模型网关**：

| 字段 | 说明 |
|---|---|
| 网关类型 | 当前支持 `LITELLM` |
| 网关名称 | 平台内显示名 |
| 网关地址 | **控制面**访问网关的 URL |
| Agent 访问地址 | **智能体 VM** 访问网关的 URL |
| Master Key | 网关管理 API 的主密钥 |
| 默认路由策略 | 简单分流 / 最少繁忙 / 基于延迟 / 基于用量 v2 / 基于成本 |

填好地址与 Master Key 后点 **测试连接**，通过再 **保存**。

::: danger 两个地址不要填成同一个
控制面和智能体 VM 在网络上处于不同位置：

| | 单机形态下典型值 |
|---|---|
| 网关地址（控制面用） | `http://litellm:4000` —— compose 网络内的服务名 |
| Agent 访问地址（VM 用） | `https://<EXTERNAL_IP>/litellm/` —— 经 console 反代的对外入口 |

把内部地址填进「Agent 访问地址」，下发到 VM 的配置就是不可达的，agent 调模型必然超时，而控制台上的「测试连接」却是绿的 —— 这种「控制台正常但 agent 用不了」的故障，九成出在这里。
:::

::: warning Master Key 不回显
Master Key 仅随本次请求安全提交，不会回显、也不会存在浏览器里。编辑时留空表示不修改。
:::

## 同步机制

平台会自动与网关同步**模型目录、轮询策略和连接状态**。你在[模型管理](/console/models)和[网关路由](/console/routes)里的改动，都是先落平台库、再推送到网关。

### 列表

| 列 | 说明 |
|---|---|
| 网关名称 · 网关地址 | 支持搜索 |
| 默认路由策略 | 该网关的缺省分派策略 |
| 连接状态 | 网关是否可达 |
| 同步状态 | 已同步 / 同步中 / 部分同步 / 失败 / 未同步，附「xx 前已同步」 |
| **后端模型数** | 网关侧当前登记的模型数量 |
| 创建 / 更新时间 | 排序字段 |

行内操作：**立即同步**、**删除**。

### 同步状态面板

页面底部的 **当前同步状态** 给出全局摘要：

- 最近同步时间
- `N 个网关同步成功，M 个网关需要处理`
- **同步日志概要** —— 失败时这里有具体原因

| 状态 | 含义 | 处理 |
|---|---|---|
| 同步正常 | 全部推送成功 | — |
| 同步中 | 正在推送 | 等待 |
| 部分异常 | 部分模型 / 策略推送失败 | 看日志概要，多为 Master Key 变更或上游配置非法 |
| 尚未同步 | 从未成功同步 | 点「立即同步」 |

::: tip 后端模型数对不上
「后端模型数」是网关侧的真实数量。它和你在模型管理里看到的条数不一致时，说明有推送没成功 —— 点「立即同步」，然后看同步日志概要。
:::

## 删除网关

二次确认后，最终确认需**输入网关名称**。

::: danger 删除会连累三类对象
删除后该网关停止同步，其下的**模型、路由、虚拟密钥**都会失去归属。已经在用这些密钥的智能体会立即调不通。操作不可撤销。
:::

## 与其他页面的依赖关系

```
模型网关接入（这一页）
   ├─▶ 模型管理     —— 每个模型归属一个网关
   ├─▶ 网关路由     —— 每条路由归属一个网关
   └─▶ 密钥管理     —— 每个虚拟密钥归属一个网关
                        └─▶ 部署智能体时绑定到实例
```

所以顺序永远是：**先接网关 → 再登记模型 → 再建路由 → 再发密钥 → 最后部署**。

## 接外部网关

除了平台内置的那个 litellm，也可以接企业已有的 LiteLLM 实例：

| 场景 | 网关地址 | Agent 访问地址 |
|---|---|---|
| 用平台内置 litellm | `http://litellm:4000` | `https://<EXTERNAL_IP>/litellm/` |
| 接外部独立 litellm | `http://gw.corp.lan:4000` | `http://gw.corp.lan:4000`（VM 也能直连时可相同） |

接多个网关时，模型 / 路由 / 密钥各自归属，互不干扰 —— 适合「研发网一套、生产网一套」的隔离需求。

## 常见问题

| 现象 | 处理 |
|---|---|
| 测试连接失败 | 网关地址控制面是否可达（进 backend 容器 `curl` 一下）；Master Key 是否正确 |
| 状态「未同步」 | 点「立即同步」；看同步日志概要 |
| 状态「部分异常」 | 日志概要里有失败原因；常见是某个 spec 的上游配置非法 |
| 控制台测试正常但 agent 调不通 | 两者用的是不同地址 —— 排查 VM 到「Agent 访问地址」的连通性 |
| 后端模型数为 0 | 尚未登记模型，或推送全部失败 |
| Master Key 轮换后全面报错 | 更新网关接入里的 Master Key，然后重跑 `./install.sh` 让 prometheus 抓取凭据一并更新 |
