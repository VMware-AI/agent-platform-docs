# 模型网关接入

> 系统配置 → 模型网关接入 · 需要 <span class="ap-badge admin">admin</span>

配置并管理 **LiteLLM** 等大模型网关的接入。所有模型调用都经由网关代理，这是平台做限流、预算、审计与计量的钩子所在。

## 接入一个网关

点 **接入模型网关**，填写：

| 字段 | 说明 |
|---|---|
| 网关类型 | 当前支持 LiteLLM |
| 网关名称 | 平台内显示名 |
| 网关地址 | **控制面**访问网关的 URL。单机形态下可用容器网络地址 `http://litellm:4000` |
| Agent 访问地址 | **智能体 VM** 访问网关的 URL。单机形态下走 console 反代：`https://<EXTERNAL_IP>/litellm/` |
| Master Key | 网关管理 API 的主密钥。仅随本次请求提交，不会回显、不会存进浏览器 |
| 默认路由策略 | 简单分流 / 最少繁忙 / 基于延迟 / 基于用量 v2 / 基于成本 |

填好地址与 Master Key 后点 **测试连接**，通过再 **保存**。

::: danger 两个地址不要填成同一个
控制面和智能体 VM 在网络上处于不同位置。把内部地址（`http://litellm:4000`）填进「Agent 访问地址」，会导致下发到 VM 里的配置不可达，agent 调用模型必然超时。
:::

## 同步机制

平台会**自动**与网关同步模型目录、轮询策略与连接状态。列表页展示：

| 列 | 说明 |
|---|---|
| 网关名称 · 网关地址 | 支持搜索 |
| 默认路由策略 | 该网关的缺省分派策略 |
| 连接状态 | 网关是否可达 |
| 同步状态 | 已同步 / 同步中 / 部分同步 / 未同步，附「xx 前已同步」 |
| 后端模型数 | 网关侧当前登记的模型数量 |
| 创建 / 更新时间 | 排序字段 |

行内操作：**立即同步**、**删除**。

页面底部的 **当前同步状态** 面板给出全局摘要：最近同步时间、成功 / 需处理的网关数、同步日志概要。

::: tip 同步状态「部分同步」怎么办
说明部分模型或策略推送失败。先看同步日志概要里的失败原因，多半是网关侧 Master Key 变更或上游模型配置非法。修正后点「立即同步」。
:::

## 删除网关

二次确认后，最终确认需要**输入网关名称**。删除后该网关停止同步，其下的模型、路由与虚拟密钥都会失去归属，操作不可撤销。

## 与其他页面的关系

```
模型网关接入（这一页）
   ├─▶ 模型管理     —— 每个模型归属一个网关
   ├─▶ 网关路由     —— 每条路由归属一个网关
   └─▶ 密钥管理     —— 每个虚拟密钥归属一个网关
```

因此**先接网关**，模型 / 路由 / 密钥页面的「模型网关」下拉才有选项。

## 常见问题

| 现象 | 处理 |
|---|---|
| 测试连接失败 | 网关地址控制面是否可达（`curl` 一下）；Master Key 是否正确 |
| 状态「未同步」 | 点「立即同步」；看同步日志概要 |
| 智能体调用超时但控制台测试正常 | 检查的是两个不同地址 —— 排查 VM 到「Agent 访问地址」的连通性 |
| 后端模型数为 0 | 尚未在[模型管理](/console/models)里登记模型，或同步未完成 |
